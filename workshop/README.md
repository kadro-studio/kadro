# Мастерская Kadro

Плагин WordPress `kadro-workshop` — сервер мастерской: пользователи публикуют из программы эффекты, переходы, элементы, фильтры, стили титров, LUT, темы и шаблоны проектов, а остальные устанавливают их одним кликом. Программа и страница [kadro.studio/workshop](https://kadro.studio/workshop/) обращаются к нему через REST API `kadro/v1`.

## Что внутри

- Тип записей «Элементы Kadro» (`kadro_item`) и метки (`kadro_tag`). Файлы хранятся в `wp-content/uploads/kadro-workshop` с запретом прямого доступа и отдаются только через API.
- Аккаунты, как на обычных сайтах, — свои страницы в стиле Kadro на трёх языках (украинский, русский, английский: `?lang=`, иначе язык пользователя или браузера). С включёнными постоянными ссылками у страниц короткие адреса, а `/?kadro=…` работает всегда:
  - `/join/` — регистрация: имя, e-mail, пароль и согласие с правилами; защита от ботов (скрытое поле, не больше 5 регистраций в час с адреса, обычные фильтры WordPress `registration_errors`).
  - `/login/` — вход по имени или e-mail (не больше 10 неудачных попыток за 15 минут с адреса), «Запомнить меня», вкладки «Войти | Создать аккаунт».
  - `/forgot/` и `/reset/` — сброс пароля ссылкой из письма (24 часа, одна ссылка — один раз; ответ одинаковый, есть аккаунт или нет).
  - `/connect/` — «Подключить Kadro» одной кнопкой.
  - `/account/` — страница аккаунта: имя для показа (чужие имена и логины заняты), смена e-mail с подтверждением на новый адрес, пароль (смена выводит из других браузеров, Kadro остаётся), Google и Discord, список компьютеров с Kadro с кнопкой «Отключить», мои публикации со статусом и причиной отклонения, выход и удаление аккаунта вместе с публикациями (аккаунты модераторов удаляет администратор).
  - `/confirm/` — ссылки из писем.
  - `/oauth/google/` и `/oauth/discord/` — вход через Google и Discord.
- Вход через Google и Discord: кнопки «Продолжить с Google / Discord» появляются, когда в «Элементы Kadro → Настройки» вставлены client ID и secret (как их получить — ниже). Впервые человек выбирает имя и соглашается с правилами; e-mail уже подтверждён сервисом. Если аккаунт с этим подтверждённым e-mail уже есть, вход присоединяется к нему (кроме модераторов: они подключают сервис сами на странице аккаунта). Картинка профиля берётся из сервиса. Пока у такого аккаунта нет своего пароля, его можно задать на странице аккаунта или через «Забыли пароль?».
- Публиковать можно после подтверждения e-mail по ссылке из письма (письмо можно отправить ещё раз из программы или со страницы аккаунта); аккаунты, созданные иначе (администратор, приглашённые), считаются подтверждёнными.
- Страницы WordPress ведут на эти: «Регистрация» → `/join/`, «Забыли пароль?» → `/forgot/`, ссылки «Войти» на сайте → `/login/`. Подписчиков из консоли (`/wp-admin/`, профиль) отправляет на `/account/`, панель администратора им не показывается. Сам `wp-login.php` и вход в консоль остаются для администратора.
- Модерация: публикации обычных пользователей попадают в «На утверждении», редакторы и администраторы публикуют сразу. Модераторы проверяют прямо в программе (вкладки «На проверке» и «Жалобы» в «Мастерской»): «Одобрить» или «Отклонить» с причиной — элемент возвращается автору черновиком, причину он видит в программе и получает письмом. Новая версия снова идёт на проверку. Администратор получает письмо о каждой новой публикации на проверку и о первой жалобе на элемент. Счётчик ожидающих — и рядом с пунктом меню в админке, колонка «Жалобы» — в списке элементов.
- Жалобы: вошедшие пользователи жалуются на опубликованное с причиной (одна жалоба от человека); модератор оставляет элемент или снимает его с публикации.
- Доверенные авторы: после N одобренных публикаций (по умолчанию 3, «Элементы Kadro → Настройки», 0 — проверять всегда) автор публикует без проверки.
- Проверка каждого файла по виду: моды (те же правила, что в программе), LUT (размер и число строк), фильтры, стили, темы и шаблоны. В шаблоне не может быть путей к файлам: все медиа — пустые слоты.
- Лайки, счётчик скачиваний (раз в сутки с одного адреса), лимит публикаций в день.
- Страница элемента на сайте с кнопками «Открыть в Kadro» (`kadro://workshop/item/ID`), «Скачать» и «Нравится».

## Установка

1. Соберите архив: `npm run workshop:zip` → `release/kadro-workshop.zip`.
2. В WordPress: «Плагины → Добавить новый → Загрузить плагин», выберите архив и активируйте.
3. «Настройки → Общие»: включите «Любой может зарегистрироваться» с ролью «Подписчик».
4. «Настройки → Постоянные ссылки»: любой вариант, кроме «Простые» (нужно для REST API).
5. Сайт должен работать по HTTPS: пароли приложений WordPress без него отключены.
6. «Элементы Kadro → Настройки»: публикация без проверки (по умолчанию выключена), лимит публикаций в день и вход через Google и Discord.

### Вход через Google и Discord

Адрес возврата для каждого сервиса показан в настройках плагина (например, `https://workshop.kadro.studio/oauth/google/`); его нужно вписать в сервисе точно так же.

- Google: [console.cloud.google.com](https://console.cloud.google.com/apis/credentials) → создайте проект → «OAuth consent screen» (тип External, название Kadro Workshop, e-mail поддержки, домен kadro.studio; доступы `openid`, `email`, `profile`) → «Credentials → Create credentials → OAuth client ID», тип «Web application», в «Authorized redirect URIs» — адрес возврата. Client ID и secret — в настройки плагина. Пока приложение в режиме Testing, войти могут только добавленные тестовые пользователи: опубликуйте его («Publish app»), проверка Google для этих доступов не нужна.
- Discord: [discord.com/developers/applications](https://discord.com/developers/applications) → «New Application» → «OAuth2»: «Redirects» — адрес возврата, «Client ID» и «Reset Secret» → в настройки плагина.

Без client ID кнопка сервиса не показывается.

Программа ищет мастерскую по адресу `https://workshop.kadro.studio` (`WORKSHOP_URL` в `src/shared/brand.ts`; для проверки на своём сервере — переменная окружения `KADRO_WORKSHOP_URL`). Сайт и программа берут адрес мастерской и признак `open` из `website/workshop.json` (программа — с kadro.studio, кэш на 30 минут). Чтобы открыть мастерскую или перенести сервер, достаточно поменять этот файл.

## Вход из программы

Пользователь нажимает «Войти» в программе. Программа открывает страницу WordPress «Авторизовать приложение» (`authorize-application.php` с `app_id` Kadro и `lang`), а плагин 1.2 ведёт с неё на свою страницу входа и затем на `/connect/`: одна кнопка «Подключить Kadro» создаёт пароль приложения и возвращает его в Kadro ссылкой `kadro://auth`, как это делает сам WordPress. Так входят и старые версии программы. Пароль хранится зашифрованным (Electron safeStorage) и в любой момент отключается на странице аккаунта («Kadro на ваших компьютерах»). Основной пароль пользователя программа не видит. Кнопка «Мой аккаунт» в программе открывает `/?kadro=account`.

## API

| Метод | Путь | Доступ |
| --- | --- | --- |
| GET | `/items?kind=&search=&sort=popular\|new\|liked&page=&per_page=&mine=&review=pending\|reported` | все (`mine` — после входа, `review` — модераторы) |
| POST | `/items` (multipart: `kind`, `title`, `description`, `tags`, `version`, `license`, `file`, `preview`, `update`) | после входа |
| GET / DELETE | `/items/{id}` | все / автор и редакторы |
| GET | `/items/{id}/file` | все |
| POST | `/items/{id}/like` | после входа |
| GET | `/me` (имя, логин, `confirmed`, `moderator`; модераторам — `pending`, `reported`) | после входа |
| POST | `/me/confirm` — отправить письмо с подтверждением ещё раз (не больше 3 в час) | после входа |
| POST | `/items/{id}/review` (`action`: `approve`, `reject` с `reason`, `dismiss` — снять жалобы) | модераторы |
| POST | `/items/{id}/report` (`reason`) | после входа, не на своё |

Ошибки, которые программа объясняет на языке пользователя: `kw_unconfirmed` (403, e-mail не подтверждён) и `kw_resend_limit` (429). Элемент в ответах дополнительно содержит `own`, `rejected` (причина — автору и модераторам), `reports` и `reportReasons` (модераторам).
